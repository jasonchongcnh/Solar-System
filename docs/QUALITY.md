# 網站品質檢查

更新日期：2026-10-03。目標是以 Awwwards、Webby Awards 與 FWA 所重視的設計製作、互動與整體體驗為參考，提升能源管理平台的品質。獲獎仍由各獎項評審認定；自動測試與自評是品質證據，並非獎項認證。

## 設計方向

以操作人員的日常工作為核心：清楚辨認資料來源、快速掃描模組狀態、查看裝置詳情，再進行控制。石墨色導覽、明亮資料區、綠色狀態與藍色遙測建立清晰層級；六角太陽能模組以實際狀態呈現，保持產品辨識度。

| 面向 | 落實項目 | 驗證方式 |
| --- | --- | --- |
| 視覺製作 | 統一字體、數字、Lucide 圖示、間距與控制尺寸 | 手機與桌面逐頁截圖 |
| 結構與導覽 | 六個功能頁、手機選單、可操作的搜尋結果 | 兩種語言與六種寬度的回歸測試 |
| 資料可信度 | 圖表與表格共用遙測模型，示範數據標示來源，缺失量測顯示 `--` | 指標一致性與 Hall-only 封包測試 |
| 互動 | 模組詳情、鍵盤陣列選取、可點選的裝置編號、開關與模式狀態 | 滑鼠、鍵盤及觸控尺寸檢查 |
| 無障礙 | 跳至內容、表單標籤、具名控制、焦點管理、Esc 關閉與 reduced motion | axe WCAG A/AA、Tab 與 Space 測試 |
| 效能與可靠性 | 本機圖示、系統字體、精簡圖示包、相同來源的靜態資產 | 資產大小、請求失敗、瀏覽器錯誤與硬體回歸 |

## 修整紀錄

1. 整理資訊層級與配色，讓狀態、輸出及陣列分區清楚。
2. 移除總覽固定圖表，接上共用資料；搜尋改成全部裝置及功能頁的實際比對。
3. 根據截圖修正英文漏譯、手機縮放位置、登入覆蓋層、舊圖示及開關滑塊。
4. 根據 axe 結果提高文字對比；補上對話框焦點返回、鍵盤操作及表單標籤。
5. 精簡 Lucide 圖示包，統一 Array Lab 視覺，加入可重跑檢查與 CI 證據輸出。
6. 加入淺色、深色與跟隨系統外觀，涵蓋登入、對話框、表格及 Array Lab；偏好保存在目前瀏覽器並同步同來源分頁。
7. 帳號升級的空白及錯誤密碼改為對話框內持續顯示，補上欄位標籤、錯誤焦點與取消驗證保護。
8. 補齊繁體中文的陣列數量、硬體狀態、韌體對話框、報告及帳號驗證標籤。修正從英文切回中文的動態文字與設定載入後的預設值，並讓陣列實驗室共用語言偏好；原始碼、封包、電子郵件地址及自訂輸入保持不變。

## 重跑方式

本輪驗證（2026-10-03）：控制台 144 個版面案例通過，24 個頁面與狀態的 axe 檢查零違規。另驗證 24 個帳號升級案例（訪客至操作員、訪客至管理員、操作員至管理員），涵蓋空白、錯誤及正確密碼。搜尋、資料更新期間的焦點返回、對話框捲動位置、模組與縮放工具分隔、Hall-only 讀數及 Array Lab 鍵盤操作均已驗證；完整硬體協定回歸也通過。

加入外觀切換圖示後，圖示包為 10,642 bytes，相較原本 357,796 bytes 減少約 97%。這是靜態資產大小的改善，不代表已量測正式部署環境的載入時間。

```powershell
npm ci
npx playwright install chromium
npm run build:icons
npm test
```

`npm run test:quality` 檢查控制台六種寬度（360、390、768、1024、1440、1920）、兩種語言、兩種外觀與六個功能頁，共 144 個版面案例，另檢查 Array Lab 手機及桌面的兩種外觀。登入、六個主要頁面、裝置對話框、三種帳號升級錯誤狀態及 Array Lab 接受自動無障礙檢查；截圖與結果寫入 `.artifacts/quality/`。

繁體中文另有 112 個介面狀態檢查，涵蓋登入、頁面、對話框、七個韌體分頁、載入失敗、斷線與資料逾時，以及陣列實驗室的動態訊息。`npm run test:locale` 可單獨重跑此檢查；`localization.json` 記錄各狀態仍未翻譯的文字。測試也比對韌體原文與原始封包，檢查語言切換不改動電子郵件地址及自訂欄位，並驗證英文預設設定能以中文重新載入。

測試使用隔離瀏覽器的示範工作階段、測試密碼雜湊與模擬硬體，不使用正式帳號或真正控制硬體。檢查涵蓋搜尋結果、HTML 安全顯示、對話框焦點、鍵盤開關、畫布像素、溢出與缺失讀數，並驗證外觀重新載入、系統偏好變更及分頁同步。帳號升級測試確認錯誤提示持續顯示、錯誤密碼不改變工作階段，以及取消尚未完成的驗證不升級帳號。

## 判斷範圍

本機 Chromium 結果不能代替真實使用者測試、實機瀏覽器檢查與正式環境的 Core Web Vitals。靜態版本的身份驗證、設定及資料仍屬示範架構；正式帳號、跨裝置資料同步與歷史儲存需要後端。儲能頁與歷史示範資料已在介面上標示。

參考來源：[Webby 官方評審準則](https://www.webbyawards.com/judging-criteria/)、[Awwwards Mobile Excellence Guidelines](https://www.awwwards.com/mobile-excellence-guidelines.pdf)、[FWA 官方網站](https://thefwa.com/)。
